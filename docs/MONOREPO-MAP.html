Read by 7 Haiku agents, 17 Oct 2026. Built on decisions already taken (ADR 0021/0022, your “Go” 16 Oct; “Halo gets its own repo, SISO gets its own repo”).

How it works on your laptop

always on2.1 GBagents, estate, packages, hq: what every agent needs
pulled when worked on4.9 GBproducts, industries, factory, library: one folder comes down when an agent works in it, goes back when it's done
GitHub only4.9 GBin the monorepo's history but never checked out unless asked
separate repos172 reposHALO, Fahmy, client-owned code, personal, data, other people's code: their own private repos, not in the monorepo

One repo, sisodias/siso. The laptop clones it without file contents (--filter=blob:none --sparse) and only the green folders are on disk. siso get apps/music brings a folder down; siso drop sends it back. Everything is always on GitHub.

Decisions I made (from the docs)

  1. Top folders = ADR 0021/0022 (already on main, your “Go”): agents/ estate/ packages/ products/ agency/factory/ agency/industries/ library/ agency/hq/ data/. The other draft (agency/ os/) folds in: agency = hq+industries+factory, os = products. This un-holds landing.
  2. Clients live as data and brand under industries/<x>/clients/<brand>; code a client owns stays its own repo.
  3. Forks (Plane, teable, AFFiNE, Hi.Events, listmonk, s3 fork) are other people's code: _reference, not the monorepo.
  4. Data (image banks, transcripts, databases, runtime state) never in the code repo: siso-data-* blocks, fetched on demand.
  5. Duplicates merge into one: Blackbox (blackbox4/5/bb5), Agent Base (5 repos), component banks (ui-base vs design-system), project-team-2, laptop-health.old, siso-ui-library → ui-hub.
